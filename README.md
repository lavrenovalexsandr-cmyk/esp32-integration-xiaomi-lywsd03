# ESP32 Home Assistant Integration — Xiaomi LYWSD03MMC

Специализированная интеграция Home Assistant для ESP32-шлюзов с BLE-датчиками Xiaomi LYWSD03MMC.

> Статус: зафиксированы целевое поведение и архитектурные решения. Реализация интеграции и MQTT-протокола будет выполняться постепенно; описанные возможности пока являются планом.

## Назначение

Интеграция обслуживает только экосистему ESP32 + Xiaomi LYWSD03MMC. Общие функции управления ESP32 (OTA, Restart, Factory Reset и базовая идентификация) остаются в универсальной интеграции esp32-integration-core и Platform Core. Xiaomi-специфичные сущности и операции не добавляются в универсальную интеграцию.

## Целевые возможности

- Автоматическое обнаружение нескольких ESP32-шлюзов.
- Отдельное HA-устройство для каждого шлюза.
- Получение от шлюзов списков обнаруженных и сохранённых Xiaomi-датчиков.
- Отдельное HA-устройство для каждого датчика и сущности температуры, влажности и батареи при наличии данных.
- Одновременная работа нескольких шлюзов.
- Сервисы добавления и удаления датчиков.
- Назначение комнаты через штатные Areas Home Assistant.

## Модель нескольких шлюзов

1. Каждый шлюз идентифицируется стабильным device identity из Platform Core.
2. Каждый шлюз регистрируется как отдельное устройство HA.
3. Датчик идентифицируется MAC-адресом и регистрируется как отдельное устройство HA.
4. Датчик связывается со шлюзом через связь device registry (via_device), если это поддерживается выбранной моделью Discovery.
5. Один шлюз обслуживает несколько датчиков; несколько шлюзов работают параллельно.
6. Команды add/remove адресуются конкретному шлюзу, не широковещательно.
7. Датчик не должен одновременно считаться управляемым несколькими шлюзами. Конфликт, когда один MAC виден нескольким шлюзам, будет разрешён в MQTT-контракте.
8. Собственные комнаты и зоны не реализуются. Пользователь назначает датчик в Area средствами Home Assistant.

## Сервисы управления

Планируемый домен сервисов: esp32-component-xiaomi-lywsd03.

- add_sensor — добавить датчик на выбранный шлюз по MAC и bind-key;
- remove_sensor — удалить датчик с выбранного шлюза по MAC.

Предварительные поля:
- gateway_id — идентификатор шлюза в HA;
- mac — MAC-адрес датчика;
- bind_key — 16-байтовый ключ в согласованном текстовом формате.

Это предварительный интерфейс. Окончательные имена полей и формат ключа будут закреплены в отдельной спецификации MQTT/API до реализации. Интеграция не хранит ключ в config entry, реестре, диагностике, событиях или MQTT state. Ключ передаётся шлюзу только в командном сообщении и хранится на ESP32 в NVS.

Удаление требует gateway_id и mac. Статусы операций не раскрывают ключ.

## Обнаруженные и сохранённые датчики

Для карточки нужны два набора данных:
- Обнаруженные — датчики, увиденные по BLE, но ещё не добавленные/не имеющие сохранённого ключа.
- Сохранённые — датчики, зарегистрированные на шлюзе, с доступностью и последними измерениями.

Данные привязаны к конкретному шлюзу. Карточка сначала выбирает шлюз, затем датчик, различая обнаруженный и сохранённый статусы.

## Назначение комнаты

Комната не передаётся по MQTT и не хранится в прошивке. Пользователь назначает устройству датчика Area через интерфейс Home Assistant. Поэтому датчики создаются как самостоятельные HA-устройства.

## Безопасность

- Никогда не логировать bind-key.
- Не публиковать ключ в state, discovery, attributes, diagnostics или событиях.
- Не хранить ключ в options/config entry интеграции.
- Не включать ключ в ошибки и подтверждения сервисов.
- Проверять MAC, длину и формат ключа до отправки.
- Маршрутизировать команды по конкретному gateway identity.

## MQTT-контракт

MQTT-контракт версии 1 согласован и зафиксирован в отдельной спецификации: [docs/MQTT_PROTOCOL_RU.md](docs/MQTT_PROTOCOL_RU.md). Английская версия: [docs/MQTT_PROTOCOL_EN.md](docs/MQTT_PROTOCOL_EN.md).

Спецификация определяет топики и payload, retained-снимки обнаруженных и сохранённых датчиков, add/remove, результаты команд, измерения, правило одного шлюза на MAC, поведение при переподключении и ограничения текущего Platform Core. Реализацию firmware и Home Assistant integration следует вести в соответствии с этим контрактом.

## Карточка

UI находится в репозитории [esp32-card](https://github.com/lavrenovalexsandr-cmyk/esp32-card). Xiaomi Sensor Manager должна:
1. позволять выбрать шлюз;
2. показывать найденные и сохранённые датчики выбранного шлюза;
3. предоставлять поле bind-key;
4. иметь кнопки «Добавить датчик» и «Удалить датчик»;
5. вызывать сервисы интеграции, а не публиковать MQTT самостоятельно.

Визуальный стиль соответствует существующим ESP32-карточкам.

## Этапы реализации

1. Утвердить MQTT-контракт совместно с firmware.
2. Реализовать основу интеграции и обнаружение нескольких шлюзов.
3. Реализовать реестры обнаруженных/сохранённых датчиков и HA Discovery.
4. Реализовать add/remove и безопасную передачу bind-key.
5. Добавить диагностику и обработку offline/reconnect.
6. Проверить несколько шлюзов и назначение Areas в HA.
